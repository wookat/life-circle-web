# 技术设计文档

> 对应赛题交付要求第 3 项：地图 API 调用策略、等时圈生成算法设计、多源 POI 数据清洗策略、
> 服务盲区识别算法。补点规划引擎与评分模型一并收录。

## 1. 地图 API 调用策略

### 1.1 双 AK 分工

| AK | 存放位置 | 用途 |
| --- | --- | --- |
| 浏览器端 AK | 服务端环境变量 → `/api/config` 下发 | GL JS API 底图、GroundOverlay 热力面、浏览器直连降级 |
| 服务端 AK | 仅服务端环境变量，永不下发 | Web API 代理：批量算路 / POI 检索 / 地理编码 / 步行路线 |

### 1.2 代理设计（`server/src/routes.ts`）

- **白名单转发**：只透传白名单参数，`ak` 由服务端注入，前端无法携带任意参数；
- **TTL 缓存**：算路 24h、POI 6h、地理编码 24h（LRU 上限 + 命中统计 `X-Proxy-Cache: HIT/MISS`）；
- **令牌桶 QPS**：place / routematrix / geocoding 均为 2 次/秒、突发上限 2（个人 AK 并发上限约 2-3，保守贴合）；
- **重试与透传**：网络错误 / HTTP 5xx 指数退避重试 2 次；百度业务错误码原样透传给前端做熔断决策；
- **失败语义**：上游失败统一 `HTTP 200 + {status:-1, message}`，前端据此无缝切换通道；
- **批量算路分片**：`routematrix/v2/walking` 单次 ≤20 对（低于上游上限留余量），多片串行调用、
  按序合并结果，任一分片失败即整体降级。

### 1.3 三级通道与熔断（`src/api.ts`）

```
server（首选）──失败──▶ client（JSONP 直连 / GL SDK 逐向算路）──失败──▶ mock（合成兜底）
```

- 每通道独立熔断器：连续 3 次失败打开 60s；配额类错误（status 302/303/304/401/429 或响应含
  「配额/限流」）打开 30 分钟；
- 通道切换在 HUD 与「数据通道」卡片实时可见，报告运行日志记录每步实际通道与耗时；
- mock 通道为**确定性合成数据**（`shared/mock.ts`，mulberry32 种子随机），保证无 AK 演示、
  CI 测试、配额耗尽兜底三种场景下行为一致。

## 2. 等时圈生成算法（扇形采样 + 空间插值）

**目标**：不获取底层路网数据，仅用少量批量测距锚点推导全方向连续可达面（评分细则第 3 条原文路径）。

1. **扇形采样**：以中心点为原点，48 个均匀方向（7.5° 步长）发射探针至直线距离
   `probeM = t·v`（15 分钟 × 80m/min = 1200m）；
2. **批量测距**：一次 `routematrix/v2/walking`（分 3 片）返回各方向真实路网步行距离；
3. **绕行系数**：`f(θ) = 实际路网距离 / 直线距离`（钳制 [0.95, 4.0]，上限 4.0 覆盖高速/铁路
   围合等强阻隔场景——此前钳 2.5 会在强阻隔方向高估可达范围），反映路网密度、
   阻隔（河流/铁路/快速路）导致的绕行；
4. **方向插值**：假设同一方向绕行系数近似恒定，`R(θ) = t·v / f(θ)` 即该方向 t 分钟可达直线
   半径；相邻方向线性插值 + 3 点圆滑窗口平滑；
5. **谐波兜底**：失败方向用道路网格谐波模型 `f = 1.12 + 0.2|sin(2θ+0.6)| + 0.08sin(5θ)`
   合成，保证结果永不中断（降级方向数在 HUD 明示）；
6. **步行时间场**（`shared/timefield.ts`）：把模型插值到 61×61、120m 步长网格，
   `t(x,y) = d(x,y)·f(θ(x,y))/v`；对场做 **marching squares** 提取 5/10/15 分钟等值线
   （链段拼接 + 道格拉斯-普克抽稀），并渲染为平滑热力面（61×61 逐格着色后双线性放大，
   GroundOverlay 贴地）。

**精度讨论**：线性外推在探测半径 1.5 倍内误差可控；热力面外圈（>18 分钟）仅作趋势参考，
盲区判定只在 t ≤ 15 分钟圈内进行，避免外推误差影响结论。

## 3. 多源 POI 数据清洗策略（`shared/poi.ts`）

1. **分类体系**：10 类民生设施 + 住宅小区（人口代理），每类默认 1 个检索关键词（核心类菜市场 2 个）——按配额友好原则精简；
2. **检索约束**：圆形区域检索（半径 2km、`radius_limit=true`）、每关键词 1 页 ×20 条、**严格串行**（请求间隔 450ms，贴合个人 AK 并发上限 2-3）；
3. **清洗**：
   - 剔除无坐标 / 零坐标记录；
   - `uid` 一级去重；
   - 名称归一（去括号注记、空白）+ 距离 <50m 二级去重（合并「XX药房(旗舰店)」类别名）；
4. **类别归因**：检索关键词 → 类别在编排层强制标注（`{...p, category: t.cat.id}`），
   避免 `guessCategory` 启发式误判；
5. **配额防线**：浏览器端 localStorage 结果缓存（约 110m 网格 + 关键词 + 半径为键，TTL 6h）——
   同一位置重复分析（如答辩反复演示）直接命中，不消耗任何检索配额。

## 4. 服务盲区识别算法（`shared/gap.ts`）

1. **人口代理**：住宅小区 POI 在网格上做盘状核（≤100m 权重 1，≤200m 权重 0.5）；
   **仅在 15 分钟圈内累计**——圈外居住区不属于该中心点服务人口；
2. **服务盘栅格化**：对三个核心类别（菜市场/药店/小学，评分细则 1km 口径）分别以每处设施
   为圆心、1km 为半径在网格上盖章，得覆盖掩码；
3. **缺失计数**：`missing(k) = 未覆盖核心类别数 ∈ {0,1,2,3}`；
   - 缺 ≥1：评分细则意义上的「盲区点位」（报告计数）；
   - 缺 ≥2 的 4 邻域连通区域聚合为「灰色斑块」（≥6 格防碎斑），重度 = 平均缺失 ≥2.7；
4. **斑块属性**：居住权重和、权重占比、加权质心、主导缺失类别（斑块内缺失率最高者）、
   主缺失类别下最远居住网格距最近设施距离、marching squares 轮廓矢量面；
5. **排序**：按居住权重降序，Top-8 上图。绿地/水域等无人网格不会产生高权重斑块，
   从机制上抑制了「把公园当盲区」的误报。

## 5. 评分模型（`shared/scoring.ts`）

```
总分 = 完整度×0.30 + 临近度×0.35 + 覆盖率×0.20 + 多样性×0.15     （0-100，A≥90/B≥75/C≥60/D≥40）
```

- **完整度**：Σ 类别权重 × min(1, 数量/理想阈值)（10 类加权）；
- **临近度**：各类最近设施直线距离阶梯衰减（200/500/800/1200/2000/3000m → 1/0.85/0.7/0.5/0.3/0.15）；
- **覆盖率**：三件套齐全居住权重 ÷ 总居住权重（人口加权）；
- **覆盖率兜底口径**：住宅小区 POI 检索不完整（如撞分页上限）而无法构成可靠分母时，
  覆盖率自动回退 **WorldPop 2020 年 100m 常住人口栅格**（api.worldpop.org，免密钥开放接口）：
  覆盖率 = 15 分钟步行等时圈多边形内常住人口 ÷ 理想步行半径（speed×minutes）圆内常住人口。
  该口径与住宅 POI 口径互不混用，评分四维仍按住宅口径剔除覆盖维度；UI 与警告区明示
  「WorldPop 栅格口径」。配额耗尽时与过街扫描同一节流原则，不再回源。
- **多样性**：类别数量分布香农熵（归一化 log 类别数）；
- **参考对标清单**：《完整居住社区建设标准（试行）》《社区生活圈规划技术指南》通行口径取整的
  10 项逐条判定（阈值可配置参考基线，报告明示口径）。

## 6. 补点规划引擎（`shared/planner.ts`）

**问题**：在灰色斑块内选择 ≤K 个补点位置与设施类别，最大化人口加权覆盖增益（最大覆盖问题）。

1. **候选生成**：每个斑块内、缺失主导类别的格，按步长抽样去密（服务盘半径/网格步长/3）；
2. **贪心迭代**：每轮枚举候选 × 服务盘（1km）内「该类缺失且有居住权重」的格，取增量权重
   最大者落点 → 虚拟写入覆盖掩码 → 剪除 400m 内近邻候选 → 迭代至增益 < 1% 总权重或达 K=3；
3. **收益量化**：每轮输出该类别居住覆盖率 before → after、新覆盖居住网格数、
   服务盘折算步行分钟（保守 1.25 绕行系数）；
4. **贪心性质**：最大覆盖的贪心算法有 (1-1/e)≈63% 近似比保证，且逐轮增益单调不增
   （单测覆盖该性质）。

## 7. 过街设施扫描

抽样 6 个方向（probeM×0.6）调 `direction/v2/walking`，拼接分段指令文本，
统计「天桥 / 地下通道 / 过街·人行横道·路口」出现频次，作为道路割裂程度的参考指标。
老年人视角的步行速度折减（52m/min）已隐含过街等待成本。

## 8. 工程决策记录

| 决策 | 理由 |
| --- | --- |
| 引擎前后端同构（shared/） | 渲染与单测共用一套实现，避免前后端行为漂移；服务端故障时前端仍可独立运行 |
| 服务端可选而非必需 | 评审快速跑通：无任何配置 `npm run dev` 即完整演示 |
| 热力面用 GroundOverlay 贴图而非逐格多边形 | 61×61=3721 个多边形会拖垮矢量渲染；canvas 贴图 GPU 友好且视觉平滑 |
| 演示数据独立成模块（shared/mock.ts） | 同一份确定性数据同时服务：无 AK 演示、单元测试、配额熔断兜底 |
| esbuild 打包服务端为 CJS 单文件 | Docker 运行镜像无需 node_modules，构建产物 ~2MB |
