# 答辩演示脚本（5 分钟版）

> 演示前自查：服务已启动（本地 `npm run dev` 或线上地址）；样例 A 坐标已定位；
> 「演示模式」徽标状态确认；本页打印一份随身带。
>
> **叙事主线：诊断 → 处方 → 验证**——每步开始前先用一句话说出本节要回答的问题。

## 演示主线（4 分 30 秒 + 30 秒缓冲）

### 0. 开场（30 秒 · 立问题）

> "国家要求居民步行 15 分钟能获得基础医疗、教育、购物、养老服务。但评估不该只回答
> 『画个圈看里面有什么』——真正的规划问题有三个：**谁缺什么？建在哪最值？建成后差多少？**
> 我们做的不是地图应用，是一条规划证据生产线：**诊断 → 处方 → 验证**。"

**操作**：指向大屏 hero——不做任何点击，先让观众看清标题与地图。

### 1. 诊断 · 谁缺什么（105 秒 · 体检 + 人群公平性）

**操作①**：中心点为样例 A（江西师范大学数字产业学院），点击「开始体检」，等 HUD 走完。

**讲解词**（指着地图）：

- "这圈红绿**热力面**不是直线距离，是 48 个方向探针在**真实路网**上批量算路后插值出的
  连续步行时间场——红色 15 分钟边界是不规则的，因为路网在绕行；"
- "报告页先看底部这条**蓝色决策摘要**——系统直接把结论写成一句话：最优先补什么、
  补在哪、覆盖率从多少到多少。诊断结果不需要你自己翻表。"

**操作②**：报告页「人群公平性对比」卡片 → 点「**生成三人群对比**」（后台复跑约 1-2 分钟，
讲解时别停，等三卡渲染完再指）。

**讲解词**（指着并排三卡）：

- "同一坐标、同一 15 分钟口径，系统对**成人 / 老年人 / 儿童（陪同）各跑一次完整体检**并排——
  不是为了多一张图：政策考核的就是公平性。看老年人这一列，可达圈收缩，圈内可达设施
  从 4 处/2 类掉到 **2 处/1 类**——成人能勉强够到超市和公交站，老年人 15 分钟内
  **什么核心设施都够不到**。极差一目了然，适老化改造该不该优先，数据自己说话。"

> 一句重音："E 级 26 分不是系统算错了——新校区周边就是还没有配套；
> 『无法评估』也不是 bug——步行圈内没采样到住宅小区，住宅 POI 口径如实判无法评估后，
> 系统自动回退 **WorldPop 2020 人口栅格**：这里 1200 米理想步行圈里常住才 1,295 人、
> 圈内仅 368 人——**新校区是真的没什么人，28% 是真实口径，不是编的数字**。"

### 2. 处方 · 建哪最值（60 秒 · 补点收益量化）

**操作**：切「规划」页签 → 指第一张建议卡的**收益统计条** → 点「地图定位」落点。

**讲解词**：

- "体检只是诊断，赛题后半句是**规划助手**。系统在缺口区用**贪心最大覆盖**求解补点，
  每条建议卡第一行就是收益：**新覆盖 N 个居住网格 · 该类覆盖率 X%→Y% · 折算约几分钟步行**——
  有限预算先建哪个，不用拍脑袋，卡片按收益排好了序。"
- "采纳后进方案工作台，可以做禁建区避让、预算扣减、A/B 方案对比——这是处方单，
  不是示意图。"

> 预案（当前点位若显示「暂无可推荐的补点」）：不绕弯，直接讲——"覆盖率无法评估时，
> 选址引擎**拒绝给无依据的推荐**，这本身是诚实口径的一部分"。然后切预检过的有推荐点位
> （或演示模式合成数据）补看收益条。

### 3. 验证 · 结果可信（60 秒 · 对照 + 精度自证）

**操作**：地址框输入「上饶市信州区中心广场」→ 定位 → 体检 → 指报告页精度行。

**讲解词**：

- "老城核心，**B 级 76 分**，圈内可达设施 **43 处/8 类**——和新校区的 E 级 26 分拉开
  五十多分的差距，系统的区分度是真能区分；老年人视角下同点 **15 处/7 类**；"
- "可信不能只靠感觉：每次分析随机抽 8 个真实算路点，和百度真实路网结果对比——
  常规街区**平均绝对误差 3.89 分钟（23.7%）**，困难地形 5.73 分钟（31.6%），
  误差透明可查，写在报告页口径区。"

### 4. 收尾 · 工程底座（30 秒 · 讲稳健）

> "最后 30 秒讲工程：服务端 AK 代理带缓存和限流；配额耗尽或上游故障时通道自动降级
> 到浏览器直连、再到合成数据——**演示永不中断**，左下角『数据通道』卡片就是实时状态。
> 单元测试全绿、类型检查零错误、Docker 一键起服、CI 自动跑，评审拿到仓库即可复现。"

### 加时亮点（60 秒 · 街道级批量体检）

**操作**：切「街道」页签 → 地址「上饶市信州区东市街道」→ 开始 → 已有缓存直接出结果。

> "把视角从单个社区拉到**整条街道**：系统自动找片区内住宅小区逐个完整体检。
> 新版结果页三样东西：**短板类别分布**——两个薄弱小区都栽在菜市场可达性，
> 区级统筹补建收益最大；**评分排行条形图**——谁好谁差一眼排序；**薄弱清单**——
> 覆盖率 71% 的青阳路和三清山东大道被精准点名。从『一个点』到『一张图』的治理视角。"

**注意**：首次执行消耗数百次检索配额；**结果进服务端缓存，重复演示免费**——到场前务必先跑一次。

### 加时亮点 2（60 秒 · 城区级试点）

**操作**：范围切「城区试点」→ 地址「上饶市信州区」→ 半径 5km / 16 点 → 开始。

> "再拉高一级——整个城区 14 个小区逐个体检，按街道分组排名：老城西市街道 91 分零薄弱；
> **茅家岭街道（高校新区组团，含样例 A）7 个小区 5 个薄弱、均分 74**——『新区配套滞后』
> 从主观感受变成可量化的街道级结论。最优最差极差 28 分，资源该往哪倾斜，数据直接给答案。"

### 被问"插值精度靠谱吗"时的标准回答（背下来）

> "我们对近似误差做了量化自证：每次分析随机抽 8 个真实算路点对比模型估计与
> 百度真实路网结果。样例 A 这种被高速与铁路围合的困难地形实测 **MAE 5.73 分钟（31.6%）**，
> 偏差集中在被匝道阻隔的扇区；常规街区 3.89 分钟（23.7%）；老年口径同点分别为
> 9.3 / 8.56 分钟——因为步速更慢，分钟级误差相应放大，这点我们如实标出。
> 绕行系数上限 4.0 覆盖强阻隔场景，且每次分析都重新自证，误差透明可见。"

## 现场故障预案

| 故障 | 预案 |
| --- | --- |
| 现场无外网 / 地图瓦片加载不出 | 直接用演示模式讲（徽标处说明：合成数据全链路一致） |
| 「生成三人群对比」等待过久 | 后台跑对比时先讲下一节，回来指三卡；全程约 1-2 分钟属正常（另两次完整体检） |
| 当前点位无补点推荐 | 照 §2 预案讲诚实口径，切预检点位或演示数据看收益条——**提前跑一次确认** |
| 检索配额告急 | 单点体检依赖浏览器端结果缓存（同位置重复分析零消耗）；街道体检结果服务端缓存 6h |
| 街道体检报"配额耗尽" | 展示已缓存的东市街道排名结果（或录屏），说明"个人 AK 日配额下每天可跑 1-2 次，已提前执行" |
| 服务端通道 210/超时 | 一句话带过："白名单传播中，系统已自动降级到浏览器通道，功能完整" |
| 体检等待过长 | "串行检索是刻意限速，保护个人 AK 并发上限；服务端批量通道约 11 秒完成"（有录屏备份） |
| 被问"为什么分数和上次不一样" | 双通道 POI 数据源差异 + 百度 POI 日间漂移（报告 §3.4 已注明），固定通道口径后稳定 |
